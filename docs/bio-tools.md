# 生物信息学工具：本地使用与实现约定

正式入口：[生物信息学工具](https://openacad.xyz/#bio)。1.1.0 已发布，生产运行与验收证据见[发布记录](deployment/production-record.md)。
工具入口为首页生物信息学区域和主导航「生物信息学」。下方启动命令供本地开发使用；首次本地验收的历史边界保留在独立验收记录中。

- 总入口：<http://127.0.0.1:5178/#bio>
- AB1：<http://127.0.0.1:5178/#bio/ab1>
- KO：<http://127.0.0.1:5178/#bio/ko>

## 启动

在 OpenAcad 根目录、已有依赖和 `server/.venv` 的环境中，分别启动：

```sh
npm --prefix web run dev
```

```sh
server/.venv/bin/python -m uvicorn app.bio:dev_app --app-dir server --host 127.0.0.1 --port 18083 --no-access-log
```

Vite 将 `/api/bio` 转发到本地 18083，原有统计 `/api` 仍转发 18082。AB1 不需要后端；KO 需要查询服务和可访问 KEGG 的网络。独立生信服务不需要 Redis/R/统计 worker，也不停止原统计服务。不要在同一端口重复启动。现有依赖安装说明见项目 README 和 server 文档。

`server/app/main.py` 同时注册生信路由，1.1.0 生产镜像已包含该集成；本地开发也可以使用上述独立服务。`/api/bio/health` 只证明服务存活，不代表 KEGG 可用。

## AB1 使用

1. 选择/拖入 `.ab1`，或点「打开真实样例」。样本信息、序列、四色峰图、质量来自文件字段；缺失项明确提示。
2. 用「每屏碱基」缩放，拖动峰图或使用前后按钮/滑块平移；输入从 1 开始的碱基位置并点击「定位」。点击峰图、质量柱或碱基，查看对应序列字符、Q 值、采样索引和四通道强度。
3. 「复制序列」复制完整序列，「导出 FASTA」保存完整序列；「区域 SVG/PNG」导出当前区域及质量图。PNG 为当前尺寸的两倍像素；SVG 保留文字，跨机器字体效果可能不同。

解析使用 ABIF 1.x 大端目录和内联值规则。优先同组 `PBAS2/PLOC2/PCON2`；缺少 PBAS2 时使用第 1 组并提示。按 `FWO_1` 映射 `DATA9–12` 四个已分析通道，不猜测缺失通道。原始采样索引直接取 PLOC，从 0 开始；用户碱基编号从 1 开始。保留 IUPAC 模糊碱基，不重新识别、修剪、反向互补或推定变异。

损坏头部、偏移越界、长度异常、重复目录、不支持版本/序列会报中文错误；缺少质量显示「缺失」，不当作 Q0。缺失/越界位置或不可靠通道停用峰图联动，避免错配。失败导入保留上一份成功文件。

上限：单文件 20 MB、100000 碱基、单数值数组 2000000 点，文件在浏览器内存解析，不上传、不保存到服务器。真实样例及校验值见 [样例来源](../web/public/examples/bio/README.md)。规范依据为 Applied Biosystems 2006 年 [ABIF 文件格式文档](https://archive.gfjc.fiu.edu/workshops/resources/literature/ABIF_File_Format.pdf)，独立解析核对使用 Biopython。

## KO 使用及结果口径

1. 粘贴每行一个 KO，或导入 UTF-8 CSV/TSV、Excel（XLSX/XLS）。粘贴默认无表头，文件默认有表头；可切换工作表、表头设置与 KO 列。预览前 5 行。
2. 点「开始转换」。接受 `K00001` 和 `ko:K00001`，统一大小写；单元格中多个 KO 可按空白、逗号、分号、竖线分隔。
3. 用状态与全文检索筛选结果。全文检索也覆盖原表字段，因此一个多 KO 原始单元格产生的其他 KO 行也可能命中搜索词。表格宽于屏幕时在表格内横向滚动。
4. CSV/Excel 导出**当前筛选的全部行**，不只当前 50 行分页。清空检索并选「全部状态」可导出全表。Excel 附来源与规则工作表。

展开规则：每条原始行 × 该行每个不同 KO × 每个不同 pathway 一条结果。同行同 KO 去重；跨行重复只合并查询，结果仍分别关联原始行。空值、无效编号、未匹配、查询失败、待查询各保留状态行。原始行号包含表头所在行；原始字段值不因 KO 标准化而改变。导出列加编号和「原表」前缀，避免重复表头覆盖。CSV 的潜在公式文本加单引号；Excel 保留原始值，不携带原表公式、格式或批注。

输入数按原表数据行；有效/匹配/未匹配/失败/待查询按去重后的有效 KO；空值按行；无效项按每行去重后的无效编号。展开结果数可超过输入数。工具只做 KO 与参考 pathway 的关系转换，不推断物种，不计算 P 值、背景集合或富集分析，也不添加通路计数图。

## 数据来源与网络处理

使用 [KEGG REST API](https://www.kegg.jp/kegg/rest/) 和 [API 手册](https://www.kegg.jp/kegg/rest/keggapi.html)：`get/ko:K00001+...` 的 PATHWAY 字段给出参考 `mapNNNNN` 编号及名称，再读取 `get/path:mapNNNNN+...` 的 CLASS。不从 BRITE 猜分类；缺失分类留空并提示。名称保留来源原文。

KEGG API 没有供此网页直接跨域读取的响应许可，故采用固定 KEGG 域名的只读后端适配器。只发送去重后的有效 KO 编号；原始表格、基因名称和其他字段不发给 OpenAcad 后端或 KEGG。每条结果及分类分别保留来源 URL 与真实获取时间；没有声称固定数据库发布版本。数据会随 KEGG 更新，内存缓存最多 6 小时，命中缓存仍展示原获取时间。

每批最多 10 个 KO、单次最多 2000 个不同有效 KO；单个 API 进程串行上游请求，最多每秒 2 次（低于 KEGG 公布的每秒 3 次限制）。文件最多 10 MB、10000 行数据、200 列。KEGG API 面向学术用户的学术用途，商业用途需按来源要求另行授权。

网络失败、429/403/5xx、内容截断与格式异常标为查询失败，不冒充未匹配；已成功的批次继续保留。单批前端两分钟超时；连续三批全失败后暂停。可停止查询，随后只重试失败和待查询项；后台已发出的只读请求可能继续完成并填充缓存。辅助分类失败保留主匹配，重新「开始转换」可补取。重新开始会重跑当前输入，重试按钮则保留成功项。

## 集成与限制

功能按需加载，不改变模板注册、计算白名单、项目 schema 或 `.openacad.json` 编码。绘图项目继续按原方式保存；AB1/KO 数据仅在当前页面会话中保留，导航切换不丢失，刷新前须自行导出，暂不写入绘图项目。

首次本地验收使用 macOS 的 Chromium、Firefox、WebKit 与 iPhone 尺寸模拟，包含 Chromium 原生触摸输入；不是实体手机或全部仪器格式认证。后续 1.1.0 的 Linux CI、生产验收和部署单独见发布记录。CSV/TSV 约定 UTF-8；历史编码 XLS、加密文件、超大工作簿及多进程部署未全面验收。多进程部署需集中协调 KEGG 限速，不能将单进程限速直接当作生产集群保证。

测试及已知限制见 [自身验收](qa/bio-tools-acceptance.md)，参考产品行为见 [独立研究记录](research/bio-tools-reference.md)。
